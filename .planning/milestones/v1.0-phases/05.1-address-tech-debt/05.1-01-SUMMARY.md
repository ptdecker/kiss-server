# Phase 05.1 Plan 01: Tech Debt Cleanup — Dead Code and peer_addr Fix Summary

**Removed 5 stale #[allow(dead_code)] annotations, deleted Url::is_safe()/query() APIs and 5 tests, and fixed peer_addr()? runtime hazard in server/mod.rs debug log**

## Accomplishments
- Removed all 5 stale forward-looking `#[allow(dead_code)]` annotations from handlers/mod.rs (mime_type, not_found, StaticFileHandler, new) and router.rs (set_fallback)
- Deleted dead `Url::is_safe()` and `Url::query()` methods (zero production call sites) plus 5 associated tests; test count reduced from 87 to 82
- Fixed latent runtime hazard: `stream.peer_addr()?` in debug log now uses `unwrap_or_else` with sentinel address — a client dropping between request parse and the debug line no longer causes early return without a response
- `cargo clippy -- -D warnings` passes with zero warnings; `cargo test` reports 82 passing, 0 failing

## Files Created/Modified
- `src/handlers/mod.rs` — Removed 4 stale dead_code annotations (mime_type, not_found, StaticFileHandler struct, StaticFileHandler::new); all items now used in production
- `src/server/router.rs` — Removed 1 stale dead_code annotation (set_fallback); now called from main.rs
- `src/url/mod.rs` — Deleted Url::query() method, Url::is_safe() method, and 5 test functions (query_returns_string, is_safe_dotdot, is_safe_encoded_dotdot, is_safe_normal_path, is_safe_invalid_decode)
- `src/server/mod.rs` — Replaced `stream.peer_addr()?` with `stream.peer_addr().unwrap_or_else(|_| "0.0.0.0:0".parse().unwrap())` two-liner

## Decisions Made
- Removed 5 stale `#[allow(dead_code)]` annotations rather than leaving them — forward-looking annotations are correct at time of writing but must be cleaned up once the code they protect is in production use
- Deleted `Url::is_safe()` and `Url::query()` entirely rather than suppressing their dead_code warnings — zero production call sites means they add API surface with no benefit
- `peer_addr()` fallback uses `unwrap_or_else(|_| "0.0.0.0:0".parse().unwrap())` — sentinel SocketAddr preserves the `{:?}` format specifier in the debug log without changing the log format
