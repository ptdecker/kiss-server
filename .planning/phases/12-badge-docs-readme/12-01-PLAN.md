```
# Architecture

Brief intro: kiss-server is a from-scratch HTTP/1.1 static file server. No external dependencies beyond the `log` crate facade. This document explains the core design patterns and key decisions.

## Handler / Context / Router

Explain the three-part abstraction:
- **Handler trait**: `fn handle(&self, ctx: &mut Context)` — any struct implementing Handler can process requests. In-place mutation of Context avoids reconstruction overhead.
- **Context**: Wraps the incoming request and the TCP stream. Handlers read the request from Context and write the response through it. Context owns the connection lifecycle.
- **Router**: Maps URL paths to Handler implementations. Uses `set_fallback()` for the static file handler — unmatched routes fall through to file serving rather than returning 404 immediately.

## Thread Pool

- Fixed-size thread pool (configurable) for concurrent connection handling.
- Synchronous blocking I/O — each connection gets a thread from the pool.
- No async runtime (no tokio). The thread pool is sufficient for the project's goals.
- Worker threads receive jobs via a shared `mpsc` channel behind a `Mutex<Receiver>`.
- Graceful-ish shutdown: Drop sends N shutdown signals (one per worker), then joins all threads.

## Static File Serving

- `StaticFileHandler` implements the Handler trait.
- Serves files from a configurable root directory (`--root` CLI arg, required).
- Binary-safe reads — files are read as `Vec<u8>`, not as strings.
- MIME detection from file extension (10+ types with `application/octet-stream` fallback).
- Path traversal prevention: `canonicalize()` the requested path, then verify it `starts_with(root)`. Returns 404 (not 403) on traversal attempts to avoid leaking path existence.

## Error Handling

- `Result` propagation throughout — no `unwrap()` on unhappy paths.
- Custom error type wraps `String` for simplicity.
- Malformed/non-UTF-8 HTTP requests return 400 (not panic).
- Mutex poison in thread pool handled via `unwrap_or_else` recovery.
- ThreadPool Drop uses `let _ = thread.join()` to avoid panic propagation.
```
