## Implementation Decisions

### Dead Code: url/mod.rs

- **D-01:** Move `pct_encode` and `pct_decode` into the `#[cfg(test)]` block — they are only
  called from tests; the module-level placement with `#[allow(dead_code)]` was incorrect.

### Dead Code: time/mod.rs

- **D-02:** `to_imf_fixdate()` — keep, remove `#[allow(dead_code)]` (used in production at
  `server/mod.rs` lines 111 and 212, and also in tests).
- **D-03:** `weekday_from_days()` — keep, remove `#[allow(dead_code)]` (called by
  `to_imf_fixdate()`; transitively used in production).
- **D-04:** Delete `days_in_month()` — no callers anywhere; trivial to recreate if needed.
- **D-05:** Delete DateTime accessor methods `year()`, `month()`, `day()`, `day_of_year()`,
  `is_leap_year()` — no callers anywhere (not in production, not in tests); trivial to
  recreate; this is a binary crate, not a library.

### Dead Code: server/response.rs

- **D-06:** Remove `#[allow(dead_code)]` from the `impl Response` block and let clippy
  surface whatever is genuinely unused; address each surfaced item individually.

- **D-08:** Delete `test.js` — not referenced anywhere; JS MIME tests use in-memory fixtures.
- **D-09:** Delete `hello.html` — not the source of the production Hello World page
  (that is generated by `scripts/setup-webroot.sh` heredoc on EC2).
- **D-10:** Delete `404.html` — 404 responses are generated programmatically.
- **D-11:** Delete `aws-ec2.sh` — stray script, not referenced anywhere.
- **D-12:** Delete `HOSTING.md` — superseded by `docs/ci-cd.md`.
- **D-13:** Delete `package-lock.json` — no `package.json` in the repo.

### TODO Comments: server/mod.rs

- **D-14:** Delete both TODO comment blocks (HTTP/1.1 RFCs and URI RFCs).
  GitHub issues #24 (keep-alive) and #25 (conditional GET) capture the actionable
  compliance gaps. RFC 3986 and RFC 6454 are not relevant to static file serving scope.

### Planning Directory: Untrack from Git

- **D-15:** Add `.planning/` to `.gitignore` — planning artifacts are local-only; they do
  not belong in the repository.
- **D-16:** Run `git rm -r --cached .planning/` to untrack all currently-tracked planning
  files without deleting them from disk. Commit the removal. After this, `.planning/`
  exists locally but is invisible to git.

### CI/CD Deprecation Warnings

- **D-17:** Bump `actions/checkout@v4` to the latest tag that supports Node.js 24 in both
  `ci.yml` and `cd.yml`. Verify the warning clears.
- **D-18:** Bump `softprops/action-gh-release@v2` to the latest tag that supports Node.js 24
  in `cd.yml`. Verify the warning clears.
- **D-19:** The `DEP0040 punycode` warnings come from these same actions internally and will
  clear when the action versions are bumped.

### GitHub Releases: Naming and CHANGELOG Enforcement

- **D-20:** Create `CHANGELOG.md` using Keep a Changelog format
  (https://keepachangelog.com/en/1.1.0/). Include entries for v1.0.0 and v1.1.0 as the
  initial content.

- **D-21:** Release name format: `vX.Y.Z (short-sha)` — e.g., `v1.1.0 (db5ff29)`.
  Tag name format: `vX.Y.Z` (standard semver git tag).

- **D-22:** CD pipeline must enforce the following before creating a GitHub Release:
  1. The commit being deployed must have a `vX.Y.Z` semver tag — fail the pipeline if absent.
  2. `CHANGELOG.md` must contain an entry for that exact version tag — fail the pipeline if absent.
  Pipeline fails hard on either violation; deployment does not proceed.

- **D-23:** Release body is populated from the CHANGELOG.md entry for the deployed version tag.

- **D-24:** Developer deploy flow: bump CHANGELOG.md → commit → tag (`git tag vX.Y.Z`) →
  push tag and prod together (`git push origin vX.Y.Z origin/main:prod`).

- **D-25:** The test release `deploy/db5ff29fabe6dc0bcc2be92ebbe2b35e17acaefd` has already
  been deleted as part of the discuss-phase session.

### Markdown Style: "/" Replacement

- **D-26:** Replace all "/" used as prose shorthand (e.g., "and/or", "CI/CD" prose references,
  "build/run") with proper English alternatives — "and", "or", "neither X nor Y",
  "X, Y, or Z" — as context demands.
- **D-27:** Scope: user-facing `.md` files only — `README.md`, `CLAUDE.md`, `docs/`,
  `scripts/README.md`. Exclude `.planning/` (internal tooling artifacts).
- **D-28:** Exception: technical path notation (`src/server/mod.rs`), URL paths (`/var/www/`),
  and established acronyms where the slash is part of the name (e.g., `CI/CD` as a proper
  noun reference in a heading or badge) are left unchanged. Only prose shorthand is replaced.

### Justfile

- **D-29:** Keep Just. Existing commands (`lint`, `build`, `run`, `test`, `build-docs`, `docs`)
  are retained and audited for correctness.

- **D-30:** Add the following new recipes:
  - `verify-dns` — runs `scripts/verify-dns.sh`
  - `branch-protection` — runs `scripts/setup-branch-protection.sh`
  - `prod-protection` — runs `scripts/setup-prod-protection.sh`
  - `deploy` — tags and pushes to prod: requires `VERSION` argument;
    runs `git tag vVERSION && git push origin vVERSION origin/main:prod`

- **D-31:** Documentation placement:
  - `CLAUDE.md` — all Just commands (for Claude's reference)
  - `docs/ci-cd.md` — pipeline-related Just commands (`deploy`, `verify-dns`,
    `branch-protection`, `prod-protection`)
  - `README.md` — non-pipeline commands (`lint`, `build`, `run`, `test`, `build-docs`, `docs`)

### Claude's Discretion

- Exact CHANGELOG.md content for v1.0.0 and v1.1.0 entries (derive from git log and
  ROADMAP.md; use Added/Changed/Fixed/Removed sections per Keep a Changelog convention)

- Whether to use `grep` or a small script for CHANGELOG parsing in the pipeline
- Exact wording of prose "/" replacements (use best English judgment per context)
