**Overhaul cd.yml for semver release flow (D-21, D-22, D-23, D-24):**

The CD pipeline must be restructured to:
1. **Validate a semver tag exists** on the deployed commit
2. **Validate CHANGELOG.md** has an entry for that version
3. **Extract CHANGELOG section** as release body
4. **Create GitHub Release** with semver tag name and proper naming

Replace the existing `cd.yml` with this structure (keeping the existing build, SSH setup, deploy, and verify steps intact):

```yaml
name: CD

on:
  push:
    branches: [prod]

env:
  CARGO_TERM_COLOR: always

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: write

    steps:
      - uses: actions/checkout@v4.2.2
        with:
          fetch-depth: 0

      - name: Validate semver tag
        id: version
        run: |
          # Find a semver tag (vX.Y.Z) pointing at HEAD
          VERSION_TAG=$(git tag --points-at HEAD | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' | head -1)
          if [ -z "$VERSION_TAG" ]; then
            echo "::error::No semver tag (vX.Y.Z) found on commit $(git rev-parse --short HEAD). Tag the commit before deploying."
            exit 1
          fi
          echo "tag=$VERSION_TAG" >> "$GITHUB_OUTPUT"
          echo "Found version tag: $VERSION_TAG"

      - name: Validate CHANGELOG entry
        id: changelog
        run: |
          TAG="${{ steps.version.outputs.tag }}"
          # Strip leading 'v' for CHANGELOG lookup: v1.1.0 -> 1.1.0
          VERSION="${TAG#v}"
          # Extract section between ## [VERSION] and the next ## [ heading
          BODY=$(sed -n "/^## \[${VERSION}\]/,/^## \[/{/^## \[${VERSION}\]/d;/^## \[/d;p;}" CHANGELOG.md)
          if [ -z "$BODY" ]; then
            echo "::error::CHANGELOG.md has no entry for version ${VERSION}. Add a ## [${VERSION}] section."
            exit 1
          fi
          # Write body to file for multi-line output
          echo "$BODY" > /tmp/release-body.md
          echo "Found CHANGELOG entry for ${VERSION}"

      - uses: dtolnay/rust-toolchain@master
        with:
          toolchain: "1.93.1"

      - uses: Swatinem/rust-cache@v2
        with:
          cache-on-failure: "true"

      - name: Build release binary
        run: cargo build --release --locked

      - name: Setup SSH
        run: |
          mkdir -p ~/.ssh
          echo "${{ secrets.EC2_SSH_KEY }}" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          echo "${{ secrets.EC2_KNOWN_HOSTS }}" >> ~/.ssh/known_hosts

      - name: Deploy to EC2
        run: |
          scp -i ~/.ssh/deploy_key -o StrictHostKeyChecking=yes \
            target/release/kiss-server \
            ec2-user@54.83.192.65:/tmp/kiss-server-new
          ssh -i ~/.ssh/deploy_key ec2-user@54.83.192.65 \
            "sudo systemctl stop kiss-server && \
             sudo mv /tmp/kiss-server-new /usr/local/bin/kiss-server && \
             sudo chmod +x /usr/local/bin/kiss-server && \
             sudo systemctl start kiss-server"

      - name: Verify service is active
        run: |
          ssh -i ~/.ssh/deploy_key ec2-user@54.83.192.65 \
            "sudo systemctl is-active kiss-server"

      - name: Create GitHub Release
        uses: softprops/action-gh-release@v2.2.1
        with:
          tag_name: ${{ steps.version.outputs.tag }}
          name: "${{ steps.version.outputs.tag }} (${{ github.sha }})"
          body_path: /tmp/release-body.md
          files: target/release/kiss-server
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Key changes from current cd.yml:
- `fetch-depth: 0` added to checkout so `git tag --points-at HEAD` works (tags require full history)
- New "Validate semver tag" step: fails pipeline if no `vX.Y.Z` tag on HEAD (D-22 point 1)
- New "Validate CHANGELOG entry" step: extracts content between `## [X.Y.Z]` and next `## [` heading; fails if empty (D-22 point 2)
- Release `tag_name` changed from `deploy/${{ github.sha }}` to `${{ steps.version.outputs.tag }}` (D-21)
