**Gathered:** 2026-03-24

<domain>
## Phase Boundary

Rename the Cargo package from `ptodd` to `kiss-server` so the compiled binary name matches the deployed binary name. Also rename the EC2 clone directory from `/opt/ptodd` to `/opt/kiss-server`. Update all affected scripts and any other references to the binary or clone dir name (not the domain `ptodd.org`).

</domain>

<decisions>
## Implementation Decisions

### Cargo package rename
- **D-01:** Change `name = "ptodd"` → `name = "kiss-server"` in `Cargo.toml`
- **D-02:** After rename, the compiled binary becomes `target/release/kiss-server` (was `target/release/ptodd`)

### EC2 clone directory rename
- **D-03:** Rename clone directory from `/opt/ptodd` → `/opt/kiss-server` on EC2
- **D-04:** Update `CLONE_DIR="/opt/ptodd"` → `CLONE_DIR="/opt/kiss-server"` in `scripts/install-kiss-server.sh`

### install-kiss-server.sh script updates
- **D-05:** Update `BINARY_SRC` to reference `$CLONE_DIR/target/release/kiss-server` (binary name now matches without a rename step)
- **D-06:** Remove or simplify Step 6 (the `ptodd` → `kiss-server` rename step) since the binary already has the correct name after Cargo package rename

### Reference audit
- **D-07:** Grep all files in `src/`, `scripts/`, `.github/` for `ptodd` references that relate to the binary name or clone dir (not `ptodd.org` domain, which stays unchanged)
- **D-08:** Update any found references consistently

### Claude's Discretion
- Whether to do the EC2 directory rename in the install script itself (mv existing /opt/ptodd → /opt/kiss-server before fresh clone) or just update the script for future runs
- Exact grep scope (can include Justfile, README, rust-toolchain.toml if references found)

</decisions>
