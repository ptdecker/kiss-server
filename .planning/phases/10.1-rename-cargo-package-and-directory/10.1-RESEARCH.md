## Summary

This phase is a pure rename with no logic changes. The Cargo package is currently named `ptodd`, which causes the compiled binary to land at `target/release/ptodd`. The install script then copies that binary to `/usr/local/bin/kiss-server` with an explicit rename step (Step 6). After changing `name = "kiss-server"` in `Cargo.toml`, Cargo places the binary at `target/release/kiss-server` directly, making the rename step in the install script redundant.

The reference audit (performed during research) found `ptodd` in five locations beyond the two primary files: a Justfile `cargo doc` path, README.md header and a stale `git clone` URL, two test temp-directory name strings in `src/handlers/mod.rs`, and the `src/main.rs` module doc comment. All are benign and easy to fix. The `verify-dns.sh` script contains `ptodd.org` and `www.ptodd.org` as domain names — those are intentional and must NOT be changed.

The EC2 directory situation requires a judgment call (Claude's discretion): the live EC2 instance currently has `/opt/ptodd` cloned. The install script is idempotent but only re-pulls if `$CLONE_DIR/.git` exists. If `CLONE_DIR` is changed to `/opt/kiss-server`, the script will do a fresh clone into the new directory, which is safe and correct — the old `/opt/ptodd` directory is left as an orphan on the live instance and can be cleaned up manually or by a future script step. No data migration of stored state is required.

**Primary recommendation:** Change `Cargo.toml` name first; verify `cargo build --release` produces `target/release/kiss-server`; then update the install script variables; then clean up the secondary references in order of descending importance (Justfile, README, src/).

**Cargo package rename mechanics (HIGH confidence — from Cargo documentation):**

- The `[package] name` field in `Cargo.toml` controls:
  1. The crate name used in `use` statements (if this were a library crate)
  2. The default binary name for `[[bin]]` targets when no explicit `[[bin]]` section exists
  3. The `cargo doc` output path: `target/doc/{name}/index.html`
- Because `Cargo.toml` has no explicit `[[bin]]` section, the binary name is derived directly from `name`. Changing `name = "kiss-server"` is sufficient — no `[[bin]]` entry is needed.
- `cargo build --release` will produce `target/release/kiss-server` immediately after the rename.

**Cargo lock file:** `Cargo.lock` stores the package name. After `Cargo.toml` rename, `cargo build` regenerates the lock file automatically. No manual lock file edit is needed.

### EC2 Directory Migration (Claude's Discretion)

Two options were identified:

**Option A: Update script only (simpler)**
Change `CLONE_DIR="/opt/kiss-server"` in the install script. On the next run, the script sees no `.git` at `/opt/kiss-server`, does a fresh clone there, builds, and installs. The old `/opt/ptodd` directory orphans on the instance.

**Option B: Add mv step in install script (cleaner EC2 state)**
Add a guard at the top of the install script:
```bash
if [ -d "/opt/ptodd" ] && [ ! -d "/opt/kiss-server" ]; then
  sudo mv /opt/ptodd /opt/kiss-server
fi
```
This reuses the existing build artifacts and avoids a full re-clone. However, after Phase 11 CD is live, fresh clones will be rare. For this phase, Option A is simpler and safe.

**Recommendation:** Option A. The CD pipeline (Phase 11) will manage deployments going forward; the install script is a one-time setup tool. A fresh clone at `/opt/kiss-server` is correct and leaves no ambiguity about which directory is authoritative.

### Anti-Patterns to Avoid

- **Editing `Cargo.lock` manually:** Never. Cargo regenerates it on next build.
- **Adding an explicit `[[bin]]` section just to set the name:** Unnecessary — `name` field in `[package]` is the correct and sufficient mechanism when there is a single binary.
- **Touching `verify-dns.sh`:** This file contains `ptodd.org` as a domain — that is domain config, not a binary/package reference. Do not touch it.
- **Touching `rust-toolchain.toml`:** No `ptodd` references exist there; no changes needed.
- **Touching `.github/workflows/ci.yml`:** No `ptodd` references exist; `./scripts/ci.sh` runs `cargo build --locked` which is binary-name-agnostic.

## Common Pitfalls

### Pitfall 1: Missing the `BINARY_SRC` Variable in Install Script
**What goes wrong:** `CLONE_DIR` is updated but `BINARY_SRC="$CLONE_DIR/target/release/ptodd"` is not — the script tries to copy a binary that no longer has that name.
**Why it happens:** Two separate variables in the script both contain `ptodd`; updating only one is a common partial-edit mistake.
**How to avoid:** Update both `CLONE_DIR` and `BINARY_SRC` in the same edit. After the rename, `BINARY_SRC` becomes `$CLONE_DIR/target/release/kiss-server`.
**Warning signs:** Script exits at Step 6 with "cp: cannot stat '/opt/kiss-server/target/release/ptodd': No such file or directory"

### Pitfall 2: Step 6 Comment Confuses Future Readers
**What goes wrong:** Step 6 in `install-kiss-server.sh` is currently commented "Install binary (rename ptodd → kiss-server)". After the Cargo rename, no renaming happens — the binary is already named correctly. Leaving the comment creates confusion.
**How to avoid:** Update the Step 6 comment to "Install binary" (no rename needed — Cargo package name now matches).

### Pitfall 3: `cargo doc` Path in Justfile
**What goes wrong:** The `docs` target in Justfile runs `open target/doc/ptodd/index.html`. After rename, `cargo doc` writes to `target/doc/kiss-server/index.html`. The `just docs` command opens a non-existent path and silently fails (or opens stale docs).
**How to avoid:** Update Justfile line 24 from `target/doc/ptodd/index.html` to `target/doc/kiss-server/index.html`.

### Pitfall 4: Treating Test Temp Dir Names as Requiring Rename
**What goes wrong:** Over-eagerly renaming `ptodd_test_` prefixes in `src/handlers/mod.rs` could break tests that assert specific directory paths.
**Why it matters:** The strings `ptodd_test_` are used as temp directory name prefixes in the OS `/tmp` directory. They do not affect the binary name or any external interface. Renaming them is cosmetic. However, if renamed, both the creation site and the cleanup/assertion site must be updated consistently.
**How to avoid:** Either rename both occurrences (to e.g. `kiss_server_test_`) or leave them alone. Both are correct. Confirm `cargo test` passes after any change.

### Pitfall 5: README git clone URL
**What goes wrong:** README line 22 shows `git clone git@github.com:ptdecker/ptodd.git`. This is the old repository name (the GitHub repo is now `ptdecker/kiss-server`). This is not a binary/package rename issue but a stale documentation reference.
**How to avoid:** Update the clone URL to `git@github.com:ptdecker/kiss-server.git`. This is a documentation fix, not a functional requirement of this phase, but it's in the audit scope.
